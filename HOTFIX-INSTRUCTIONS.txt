AI EMPOWERMENT OBSERVATORY — RESOLVER JSON HOTFIX
31 August 2026

WHAT FAILED
The weekly resolver did not fail because of the Hugging Face warning.
It failed because Qwen returned syntactically malformed JSON and
resolve_events.py tried to parse that single response once with json.loads().
The traceback does not print the raw model answer, so the exact malformed token
cannot be recovered from the log. One malformed model response was enough to
terminate the entire weekly run.

WHAT THIS HOTFIX CHANGES
1. scripts/resolve_events.py
   - requests OpenAI-compatible JSON-object output from llama.cpp first;
   - retries the same verifier call in three modes;
   - validates the relationship label after parsing;
   - if all responses are syntactically malformed, falls back conservatively to
     relationship=unclear, confidence=0 instead of crashing or auto-merging;
   - persistent HTTP/server failures still fail the stage rather than being hidden;
   - replaces the old greedy JSON regex scanner with a safer JSON object scanner.

2. scripts/reconcile_event_history.py
   - applies the same structured-JSON/retry protection to the NEXT weekly stage,
     so the pipeline cannot immediately fail there for the same reason.

3. .github/workflows/resolve-events.yml
   - passes HF_TOKEN when that optional GitHub secret exists. This only addresses
     the rate-limit warning; HF_TOKEN is NOT required for the JSON error fix.
