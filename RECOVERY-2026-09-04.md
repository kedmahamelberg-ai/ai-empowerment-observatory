# Observatory classification recovery

## What failed

GitHub run 33912230833 stopped on coverage item 47 of 221 after three responses
without a usable JSON answer. The original request allowed only 900 generated
tokens and relied on a prompt instruction to disable Qwen3 thinking. The logs
did not retain finish reasons, so they cannot prove whether those responses
were truncated or contained reasoning only. They do prove that the classifier
aborted and that passes 2 and 3 were skipped by their job conditions.

The earlier database check failure was a separate compatibility problem:
`not_available` is an internal evidence state, but the database's content-basis
column accepts `headline_only`. The compatibility mapping is retained; the
raw evidence provenance and public result continue to say no body was read.

A green repository-integrity job did not mean that classification or deployment
had succeeded. Publication was correctly blocked by incomplete/stale results.

## Durable repair

- Both classifiers explicitly disable Qwen thinking in the server template and
  request, constrain all attempts to the research response schema, and reject
  empty, partial, malformed, or truncated answers before normalization.
  Real-model testing also exposed out-of-range dimension confidence in Stage
  7C. Confidence now has a grammar-enforced 0–1 scale in steps of 0.05; it
  remains a diagnostic self-rating and never weights the substantive index.
  Each dimension also uses a conditional schema: an absent dimension has
  direction `not_present` and degree 0; a present dimension has a directional
  label and degree 1–3. This prevents contradictory presence/direction outputs.
- Relationship inference records transport version, finish reason, token count,
  sampling parameters, and prompt hash. The research codebook and classifier
  version remain compatible with the valid results already saved this week.
- A relationship model failure leaves a pending unit, continues other units,
  and checkpoints the run. Later passes retry gaps. No model failure is written
  as an insufficient-evidence finding. Publication still requires completeness.
- Both workflows permit later passes after failures and stop after completion
  or cancellation. The llama.cpp build is pinned to a specific revision, and
  the relationship jobs install only their own dependencies.
- Both article-body loaders measure actual multilingual text rather than old
  whitespace-only counts. French, Chinese, and bilingual Canadian fixtures
  exercise the loaders, not just a standalone character-count helper.
  The model context is 32,768 tokens so original-script article evidence has
  more room than the previous 12,288-token setting allowed.
- Where stronger source evidence invalidates part of an interrupted run, a
  continuation preserves still-valid results and human decisions, links copies
  to their original rows, and recomputes only the outdated results. Strict
  resume-only mode still refuses to start a replacement run.

## Operation

Normal Monday collection uses these same repaired reusable workflows.
For an interrupted current release, Actions → **Recover and Publish Current
Observatory Week** → **Run workflow** on main performs validation, recovery,
period-summary refresh, publication, and exports all developments plus a
repeatable 24-development quality sample. It does not recollect news or restart
event grouping or Stage 7C. Source bodies genuinely unavailable remain disclosed.

Completion means both classification and the Pages deployment succeed. The
published relationship artifact and source-linked review should then be checked;
the interface counters are generated from those saved results, never hardcoded.

`python -m unittest discover -s tests -v`

The regression suite executes the classifier loop against an in-memory database
and a controlled HTTP endpoint. It covers the 46-saved / failed-47 / completed-48
sequence, subsequent resume, a future week, database-compatible unavailable
evidence, evidence upgrades and preserved decisions, both multilingual loaders,
both model boundaries, publication rejection, and workflow recovery conditions.
These tests do not substitute for the live GitHub inference and deployment run.
